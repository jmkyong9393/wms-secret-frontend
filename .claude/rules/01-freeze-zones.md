# 코드 프리즈 구역 (Freeze Zones) 상세 규칙

## LangGraph 4-Agent 파이프라인 (모듈 격리 원칙)

- Vision → Policy → Critic → Report 4단계 에이전트 로직을 단일 에이전트나 단일 프롬프트로
  병합하지 않는다. 각 단계는 별도 노드/함수로 유지한다.
- 모델 배정은 비용 최적화를 위해 고정한다:
  - Vision Agent: `GPT-4o`
  - Policy / Critic / Report Agent: `GPT-4o-mini`
- 리팩토링 시에도 위 모델 배정과 4단계 분리 구조는 변경 대상에서 제외한다.
- 파이프라인 성능/비용 이슈가 있다면, 구조를 병합하는 대신 각 노드 내부 프롬프트나 전처리 로직을 개선하는 방향으로 제안한다.

- 만약 프리즈 구역을 반드시 건드려야 하는 버그(예: 보안 취약점)가 발견되면, **코드를 수정하지 말고** 문제를 요약해 사용자에게 보고하고 명시적 예외 승인을 먼저 받는다.
- 사용자가 예외 승인을 하더라도, 수정 전 해당 블록을 `archive/`에 별도 백업한 뒤 진행한다.
